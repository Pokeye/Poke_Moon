# Project content guide

Add a project only when its claims can be verified from source code, documentation, or the project owner.

## Required evidence

- Title and concise problem statement.
- Actual role and technologies used.
- Current status: `prototype`, `partial`, `in-progress`, `complete`, or `archived`.
- What works today, known limitations, and planned next steps.
- A valid repository, demo, or case-study destination when shown as a link.

## Image rules

Use local, appropriately licensed screenshots or original visuals. Include informative alt text for screenshots; mark purely decorative illustrations as decorative. Do not use a placeholder as evidence of a completed project.

## Link check

Open every external link before adding it. Omit unavailable demos rather than showing a broken or deceptive call to action.
